# Architecture Decision Records

This folder contains the Architecture Decision Records (ADRs) for OceansX V2. An ADR is a short document that captures a significant technical or architectural decision: the context that made it necessary, the options considered, the choice made, and why. ADRs are written to be read by non-technical audiences as well as engineers — each one ends with a plain-English summary that requires no technical background.

ADRs are permanent records. Once accepted, they are not deleted or rewritten when circumstances change — instead, a new ADR is written that supersedes the old one, and both remain in the record. This preserves the reasoning at each point in time.

## ADR Template

New ADRs follow the template in the architecture document (Section 13.3) and must include all sections: Status, Decided, Deciders, Context, Decision, Alternatives Considered (at least two), Consequences (Enables / Precludes / Costs / Reversibility score 1–5), and a Plain-English Summary of two paragraphs.

ADRs are numbered sequentially. The Documentation Maintainer Build Swarm agent owns all new ADR drafts. ADRs that change a prior decision supersede rather than replace — mark the old ADR `Superseded by ADR-XXXX` and add the new ADR with `Supersedes ADR-XXXX` in its header.
